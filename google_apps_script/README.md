# 지도교수 승인 메일 설정 (Apps Script)

```
구글폼 제출 → 지도교수님께 메일 → 교수님이 [승인]/[반려] → 시트 '승인상태' 칸에 기록
           → 창공시스템 동기화 → "승인"이면 대기 목록에 등록, "반려"면 승인/반려 내역에 기록
```

코드: [professor_approval.gs](professor_approval.gs)

## 설정 순서

승인을 받을 신청이 들어오는 **응답 스프레드시트마다** 한 번씩 합니다. 예를 들어 기자재 전용 시트와 캐비닛
전용 시트를 따로 쓰면 두 시트 모두에, 상상Lab 메인 시트도 받으려면 거기에도 합니다.
시트 주인 계정으로 진행하세요. 메일은 이 계정 이름으로 나갑니다.

### 1. 코드 붙여 넣기

1. 응답 스프레드시트를 엽니다.
2. 메뉴 **[확장 프로그램] → [Apps Script]** 를 누릅니다.
3. `Code.gs`에 들어 있는 내용을 지우고 `professor_approval.gs`의 내용을 전부 붙여 넣은 뒤 저장(💾)합니다.
4. 맨 위 `CONFIG`를 고칩니다.
   - `ADMIN_EMAIL`: 교수님 이메일을 찾지 못한 신청을 대신 받을 관리자 주소. 꼭 채우세요.
   - `REQUIRE_FOR`: '원하는 공간' 질문이 있는 메인 시트에서만 쓰입니다. 메일을 보낼 공간의 낱말을 적습니다.
     예를 들어 상상Lab은 교수 승인이 필요 없다면 `'상상'`, `'lab'`, `'랩'`을 지웁니다.
     기자재·캐비닛 전용 시트는 이 값과 상관없이 모든 행에 보냅니다.

### 2. 웹 앱으로 배포

교수님이 누르는 [승인]/[반려] 버튼이 열 화면입니다.

1. 오른쪽 위 **[배포] → [새 배포]** 를 누릅니다.
2. 톱니바퀴에서 유형 **웹 앱**을 고릅니다.
3. **다음 사용자로서 실행: 나**, **액세스 권한이 있는 사용자: 모든 사용자**로 정합니다.
   교수님이 구글 로그인 없이도 누를 수 있게 하려는 설정입니다. 처리는 메일마다 다른 64자리 확인 코드로만 됩니다.
4. **[배포]** 를 누르고 권한을 승인합니다.
   "Google에서 확인하지 않은 앱" 화면이 나오면 [고급] → [(프로젝트 이름)(으)로 이동]을 누릅니다. 내가 만든 스크립트라 정상입니다.
5. 나온 **웹 앱 URL**(끝이 `/exec`)을 복사해 코드 맨 위 `CONFIG`의 `WEB_APP_URL: ''` 따옴표 안에 붙여 넣고 저장합니다.
   비워 두면 스크립트가 주소를 자동으로 찾는데, 실행 환경에 따라 교수님이 열 수 없는 시험용 주소(`/dev`)가 나와
   "현재 파일을 열 수 없습니다" 화면이 뜰 수 있습니다. 나중에 주소는 [배포] → [배포 관리]에서 다시 볼 수 있습니다.

### 3. 처음 설정 실행

1. 스프레드시트 탭으로 돌아가 새로고침합니다. 메뉴에 **[창공시스템]** 이 생깁니다.
2. **[창공시스템] → [처음 설정 (트리거·칸 만들기)]** 를 누르고 권한을 승인합니다.
3. 다음이 만들어집니다.
   - 응답 시트 오른쪽 칸: `승인상태 · 확인코드 · 수신자 · 발송시각 · 재발송횟수 · 처리시각 · 반려사유`
     원래 손으로 쓰던 `승인상태`(또는 `승인여부`) 칸이 있으면 그 칸을 그대로 씁니다.
   - `교수목록` 탭
   - 트리거 2개: 폼이 제출되면 메일을 보내고, 매일 오전 9시에 결정이 없는 신청을 다시 알립니다.

### 4. 교수목록 채우기

`교수목록` 탭에 이름과 이메일을 적습니다.

| 이름 | 이메일 |
|---|---|
| 김동현 | kim@dongseo.ac.kr |

- 학생이 "김동현 교수님"처럼 적어도 띄어쓰기와 '교수님', '교수'를 떼고 찾습니다.
- 목록에 없는 이름이면 `ADMIN_EMAIL`로 대신 보냅니다. 메일 위쪽에 그 사실이 적혀 있습니다.
- **폼에서 교수님 이메일을 받지 마세요.** 학생이 자기 주소를 적어 스스로 승인할 수 있습니다.

### 5. 창공시스템 설정

1. 창공시스템 [설정] → **[지도교수 승인을 거친 신청만 받기]** 에서 승인이 필요한 구분을 체크합니다.
2. **[연동 설정 저장]** 을 누릅니다.
3. 기본값은 기자재만 체크되어 있습니다. 예전에 기자재 시트의 '승인상태'를 손으로 적던 방식과 같습니다.

체크한 구분은 시트의 '승인상태'가 "승인"이 되어야 대기 목록에 들어옵니다.
**스크립트를 붙이지 않은 시트의 구분을 체크하면 그 신청은 영영 들어오지 않습니다.** 체크와 스크립트를 함께 맞추세요.

### 6. 시험해 보기

1. `교수목록`에 내 이름과 내 이메일을 한 줄 적습니다.
2. 그 이름을 지도교수로 적어 폼을 제출합니다.
3. 받은 메일에서 [승인]을 누르고, 열린 화면에서 [처리하기]를 누릅니다.
4. 시트의 `승인상태`가 "승인"이 된 것을 확인합니다.
5. 창공시스템 [설정] → [지금 동기화]를 눌러 대기 목록에 들어오는지 봅니다.
6. 끝나면 시험한 줄을 지웁니다.

## 이미 들어와 있던 응답

스크립트를 붙이기 전의 응답에는 메일이 가지 않습니다. 보내려면 [창공시스템] 메뉴를 씁니다.

- **[선택한 행에 승인 메일 보내기]:** 고른 행에만 보냅니다.
- **[아직 안 보낸 행 모두 보내기]:** 메일을 보낸 적 없는 행에 모두 보냅니다.
  **예전 응답 전체에 메일이 가므로**, 이미 처리한 행은 먼저 `승인상태`에 "승인"이나 "반려"를 적어 두세요.

## 알아둘 것

- **코드를 고친 뒤 다시 배포할 때:** [배포] → [배포 관리] → ✏️ 편집 → 버전 **새 버전**으로 바꾸세요.
  [새 배포]로 만들면 주소가 바뀌어 이미 보낸 메일의 버튼이 동작하지 않습니다.
- **발송 한도:** 개인 Gmail은 하루 약 100통, 학교 Google Workspace 계정은 더 많습니다.
  한도를 넘기면 그 행은 `발송시각`이 빈 채로 남습니다. 다음 날 [아직 안 보낸 행 모두 보내기]로 다시 보내면 됩니다.
- **링크만 열면 처리되지 않습니다.** 메일 보안 검사가 링크를 미리 열어 볼 수 있어서, 확인 화면에서 한 번 더 눌러야 처리되게 했습니다.
  이미 처리된 신청은 다시 바꿀 수 없습니다. 바꾸려면 시트의 `승인상태`를 직접 고칩니다.
- **시트 편집 권한:** `확인코드`를 볼 수 있으면 그 신청을 처리할 수 있습니다. 응답 시트의 편집 권한은 관리자에게만 주세요.
  창공시스템 서비스 계정은 지금처럼 '뷰어'면 됩니다.
- **재알림:** 결정이 없으면 2일마다 최대 2번 다시 보냅니다. `REMIND_AFTER_DAYS`, `MAX_REMINDERS`로 바꿉니다.
- **C# 프로그램:** 이 규칙을 기자재에만 적용합니다. 캐비닛·상상Lab 승인은 웹/파이썬 버전에서만 동작합니다.
